## 2. Successes & Strengths
- **Testing Strategy:** The early investigation into mocking the Windows API paid off. We successfully mocked `pywin32` and `psutil` using `pytest-mock`, avoiding manual testing bottlenecks for foreground detection.
- **Safe Degradation:** The fallback and companion modes work perfectly to keep the assistant alive and useful when detection is uncertain or integrations fail.
- **Configurability:** Tuning parameters (polling intervals, model profiles, prompt mapping) are fully externalized to YAML, preventing code changes for behavior tweaks.

## 3. Challenges & Roadblocks
- **Mocking Quirks:** We encountered an issue with `pytest-mock` when patching `pathlib.Path.exists` (it's read-only as an instance attribute), but we learned to patch the class method instead.
- **State Validation:** Ensuring components didn't bypass the canonical state machine required strict boundary enforcement.
