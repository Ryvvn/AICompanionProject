## 2. Successes & Strengths
- **Smooth TTS/STT Integration:** Voice layers were added on top of the text baseline as intended. The adapter pattern (`AdapterResult` in `integrations/base.py`) ensured consistent contracts.
- **CPU-side Smart Choice:** Keeping STT/TTS on CPU preserves 8GB VRAM for Ollama models. An explicit test enforces no GPU libraries are imported in voice code paths.
- **Thread-Safe Design:** `speak_async()` wrapping with threading ensures TTS doesn't block the main conversation loop. `_speak_lock` prevents overlapping speech.
- **Graceful Degradation:** Text output is always delivered before TTS is attempted. All failure modes (missing executable, missing model, timeout, subprocess crash) return clean `AdapterResult` with no crashes.
- **All Stories Shipped Same Day (2026-05-11):** Excellent velocity — Stories 6.1 and 6.2 built the core adapters, 6.3 added config/CLI, 6.4 and 6.5 verified degradation patterns.

## 3. Challenges & Growth Areas
- **Scope Overlap:** Stories 6.4 and 6.5 were largely verification — their dev notes confirm all failure modes were already handled in 6.1 and 6.2. These requirements could have been absorbed into the adapter stories. Minor inefficiency.
- **Cold Start Latency:** First TTS call takes 5-7s due to Kokoro ONNX model loading. Subsequent calls are 2-4s. A `warmup()` exists but isn't called at startup.
- **Kokoro CPU Usage on i9-13900K:** Kokoro and Whisper use all available cores for maximum speed, which could theoretically compete with foreground apps (games, Unity). Process priority optimization needed for coexistence.

## 5. Significant Discoveries & Discussion Points
- **Kokoro vs Piper:** Default is Kokoro (in-process ONNX) with Piper as subprocess fallback. Kokoro has higher quality but ~2x latency compared to Piper.
- **Real-time Performance:** On i9-13900K, Kokoro processes a 50-word response in ~1-2s inference + audio playback time. Conversationally acceptable.
- **Priority-based Speech Interrupt:** Fits the "ashley_neuro" persona — high-priority items (interventions) should interrupt current speech. Normal speech drops if busy.
- **Chunked Streaming Idea:** Splitting TTS output sentence-by-sentence so the first chunk plays while subsequent chunks are generated, reducing perceived latency.
- **Process Priority:** Setting Below Normal priority on TTS/STT subprocesses would let games/Unity take CPU first while leaving leftover cores for voice. On 24-core i9-13900K this is invisible.
